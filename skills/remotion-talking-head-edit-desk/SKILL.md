# Remotion Talking-Head Edit Desk

## Goal

Turn one raw Chinese talking-head recording and optional same-folder subtitles, script, screenshots, recordings, documents, and other media into a complete local edit-desk project. First let the user decide whether the recording should be cleaned. Then perform the selected preparation plus transcription alignment, semantic directing, component routing, placement, H3 generation and retiming, captions, SFX, and asset packaging—but hand off before final composition rendering so the user can change components, variants, timing, placement, content, and materials in the local editor.

This is the human-assisted delivery adapter for `remotion-foreground-builder-auto-reference-first`. Resolve that Skill through `sharedDirectorRoot` in `config/edit-desk.local.json`. It is the single source for component code, default styles, visual variants, motion, Spoken-Beat rhythm, semantic selection, placement rules, cleaning, SFX, and H3. The edit desk calls that director and packages its result as an editable project; it does not own another director or visual library. Ordinary per-video work reads the original Skill without modifying it. When the user explicitly authorizes a reusable component or directing improvement, make that change in the original Skill, validate it there, then sync the editor. Never implement the improvement in an editor-owned component override.

Read `references/edit-desk-handoff.md` before producing any deliverable. It overrides the autonomous director's instructions at the handoff and rendering boundary.

### 1. Ask whether to clean the recording, then establish the working base

- Before running cut detection, word-level ASR solely for cutting, or rendering a clean base, ask one short binary question: `是否先处理原视频（剪气口、明显口误、重复内容）？请选择：要 / 不要。`
- Treat `要` and `不要` as equal supported paths. Do not silently choose one, and do not start expensive preprocessing while waiting. If the user's invocation already states an explicit choice, use it as the answer and do not ask again.
- Always probe the exact encoded width, height, frame rate, duration, rotation, and audio streams first.
- If the answer is `要`:
  - Run word-level ASR. Acoustic silence and breath detection may propose cuts but never authorize them alone.
  - Conservatively remove only non-semantic dead air, abandoned retakes, obvious mistake-and-immediate-correction spans, and redundant repeated phrases. Preserve meaningful pauses and uncertain content.
  - Write `analysis/clean-edit-decisions.json`, render `media/clean-base.mp4`, and write `analysis/cut-map.json` with `<directorRoot>/scripts/build-clean-base.py`.
  - Require the clean base's encoded width and height to equal the raw source exactly. Do not scale, crop, pad, stretch, reframe, or substitute a standard resolution.
  - Regenerate or validate word-level ASR against the clean base. Set the clean base as the `workingBase`; clean-output milliseconds become the `workingTimeline` authority.
- If the answer is `不要`:
  - Do not cut, rewrite, remux, or render a replacement base plate. Set the raw source itself as `workingBase` and its original milliseconds as the `workingTimeline` authority.
  - Use a reliable same-folder subtitle or word-timing file when available; otherwise transcribe for semantic timing only. ASR in this path must not authorize cuts.
  - Record `provenance.preprocessingChoice` as `raw-pass-through` so later stages do not remap timestamps through a cut map.
- Reuse an existing compatible working base, transcript, cut map, semantic timeline, foreground plan, or generated H3 asset when its recorded source fingerprint, preprocessing choice, and director fingerprint still match. Changing `要/不要` invalidates downstream timing artifacts. Never repeat expensive ASR, H3, or clean-base work solely to reinstall or reopen an unchanged project.

### 2. Direct the whole video semantically

- Discover same-folder subtitles, scripts, screenshots, operation recordings, documents, audio, and other media automatically. A companion script corrects wording but never fabricates timing.
- Build Section -> Foreground Scene -> Spoken Beat timing from the transcript aligned to the `workingTimeline`.
- Give each Section one rhetorical role. Analyze each Foreground Scene independently through real-object, information-relationship, and memory layers. These layers may appear alone or coexist.
- Select zero or one information relationship per Foreground Scene.
- Synthesize each Section title from the section's central meaning, not by blindly copying a sentence.
- Treat every Section title as the dedicated `SectionTitle` component, outside the 24 semantic foreground components. It has two selectable variants: `referenceV2` (V2 中英标题, the default for new cuts) and `standard` (经典标题). Follow the authoritative Title Layer contract in `references/layer-rules.md` under `sharedDirectorRoot`. Both start from the same whole-event placement default (`mode: preset`, `preset: leftMiddle`, `alignmentToken: sectionTitleLeft`, `visibleEdge: left`, `align: left`, `boundsMode: visibleContent`, `boundsVersion: 2`). The shared title layout owns responsive geometry. Manual whole-title drag and uniform resize are supported; preserve versioned normalized placements on load/save and apply them in preview/export. Never reset a saved title to its preset or use a generic selection rectangle. Never encode a title as `InsightFocus` or another semantic component.
- Write `analysis/semantic-timeline.json` and `analysis/foreground-plan.json` before H3 selection.
- The foreground plan must be the same plan the current authoritative Reference First director would produce for the same transcript, working timeline, and materials. The edit-desk mode changes only the final delivery boundary; it does not own a simplified director.
- Inherit its scene-level core-plus-context decision from `references/remotion-semantic-director.md` section 3.4 under `sharedDirectorRoot`. Preserve useful grounded context even when the structure is already complete. Do not run a second necessity filter or enrichment analysis here; serialize the authoritative choices into the editable project.
